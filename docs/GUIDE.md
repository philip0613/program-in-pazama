| ① | **GitHub 아이디 알려주기** | 내 아이디를 단톡방에 올리기 (모르면 github.com 로그인 → 오른쪽 위 프로필 사진 클릭 → 굵은 글씨 이름 옆 아이디) |

## 2. 프로젝트를 내 컴퓨터로 가져오기

GitHub Desktop 에서:

1. 메뉴 **File → Clone repository...**
2. 위쪽 **URL** 탭 클릭
3. 아래 주소 중 **내가 맡은 쪽**을 붙여넣기 (둘 다 해도 돼요)
   - 화면(프론트엔드): `https://github.com/philip0613/programing-in-pajama`
   - 서버(백엔드): `https://github.com/philip0613/program-in-pazama`
4. **Clone** 클릭 → 끝!

## 3. 실행해보기

1. GitHub Desktop 에서 **Repository → Show in Explorer** (맥: Show in Finder)
2. 열린 폴더에서 **`실행하기.bat`** 더블클릭 (맥: `실행하기-맥.command`)
   - 처음엔 설치 때문에 1~2분 걸려요. 까만 창은 **닫지 마세요** (닫으면 꺼져요)
   - 맥에서 "확인되지 않은 개발자" 경고가 뜨면: 파일 **우클릭 → 열기**
3. 성공하면
   - 화면: 브라우저가 자동으로 열려요 (http://localhost:5173)
   - 서버: http://localhost:8080/api/test 에 `"status":"ok"` 가 보여요

### 🔑 키값 넣기 (로그인·DB 기능 쓰려면)
1. 같은 폴더에 생긴 **`.env`** 파일을 **우클릭 → 연결 프로그램 → 메모장**
2. 단톡방에서 받은 키값을 `=` 뒤에 붙여넣고 저장
3. 까만 창을 닫고 `실행하기.bat` 다시 실행

> ⚠️ `.env` 는 비밀 파일이라 GitHub 에 올라가지 않게 설정돼 있어요. GitHub Desktop 에 안 보이는 게 정상!

### 🧪 화면 담당인데 서버가 아직 없다면? (목 모드)
`.env` 에서 `VITE_USE_MOCK=false` 를 `VITE_USE_MOCK=true` 로 바꾸고 다시 실행하면, 가짜 데이터로 화면을 만들 수 있어요.

## 4. ⭐ 매일 작업하는 순서

> 이 6단계만 기억하면 돼요. **절대 `main` 에서 바로 작업하지 않기!**

### ① 최신 코드 받기
1. 위쪽 **Current branch** 를 눌러 **`main`** 선택
2. 오른쪽 위 **Fetch origin** 클릭 → **Pull origin** 으로 바뀌면 한 번 더 클릭

### ② 내 작업 공간(브랜치) 만들기
1. **Current branch → New branch**
2. 이름 입력: `feat/하는일` (예: `feat/댓글기능`, `fix/로그인버그`)
3. **Create branch** 클릭

### ③ 코드 수정하기
**Repository → Open in Visual Studio Code** 로 열어서 코드를 고치세요.
(수정한 내용은 GitHub Desktop 왼쪽 **Changes** 에 자동으로 나타나요)

### ④ 저장하기 (Commit)
1. 왼쪽 아래 **Summary** 칸에 한 일을 짧게 적기 (예: `댓글 목록 화면 추가`)
2. 파란 **Commit to feat/...** 버튼 클릭
3. ⚠️ 버튼에 **`main`** 이라고 써 있으면 누르지 말고 ②번부터 다시!

### ⑤ GitHub 에 올리기 (Push)
오른쪽 위 **Publish branch** 클릭 (두 번째부터는 **Push origin**)

### ⑥ 합쳐달라고 요청하기 (Pull Request)
1. 화면 가운데 **Create Pull Request** (또는 **Preview Pull Request**) 클릭 → 브라우저가 열려요
2. 템플릿 칸을 채우고 초록 **Create pull request** 클릭
3. 단톡방에 "PR 올렸어요, 확인 부탁해요 🙏" 링크 공유

> 💡 하루 작업을 여러 번에 나눠서 ④⑤ 를 반복해도 돼요. PR 은 기능이 끝났을 때 한 번만!

## 5. 친구 작업 확인하고 합쳐주기

친구가 PR 을 올렸다면 (GitHub 웹사이트에서):

1. 레포 페이지 → 위쪽 **Pull requests** 탭 → 친구 PR 클릭
2. **Files changed** 탭에서 바뀐 내용 훑어보기
   - 초록 줄 = 추가, 빨간 줄 = 삭제
3. 아래 **CI** 체크가 ✅ 초록색인지 확인 (❌ 빨간색이면 친구에게 알려주기)
4. 괜찮으면 **Merge pull request → Confirm merge**

> ⚠️ **Merge 하면 실제 사이트에 바로 반영돼요.** 확실하지 않으면 단톡방에 먼저 물어보기!

## 6. 자주 생기는 문제

| 증상 | 해결 |
|---|---|
| `실행하기.bat` 을 눌렀더니 "Node.js 가 설치되어 있지 않아요" | 1-③ Node.js 설치 후 **컴퓨터 재시작** |
| `Port 5173 is already in use` / `EADDRINUSE` | 이미 켜진 까만 창이 있어요. 그 창을 닫고 다시 실행 |
| 화면에 "❌ 백엔드 연결 실패" | 서버(`program-in-pazama`)의 `실행하기.bat` 도 같이 켜거나, 목 모드 사용 |
| "로그인할 수 없습니다" | `.env` 에 Supabase 키값을 안 넣었어요 (3번의 🔑 참고) |
| Pull 할 때 **conflict** (충돌) 라고 뜸 | 친구와 같은 곳을 고쳤어요. **혼자 해결하지 말고** 캡처해서 단톡방에! |
| 실수로 `main` 에 커밋했어요 | Push 하지 말고 단톡방에 알려주세요. 같이 되돌려요 |
| 친구가 합친 최신 코드가 내 브랜치에 없음 | 메뉴 **Branch → Update from main** |

## 7. 용어 사전

| 용어 | 쉽게 말하면 |
|---|---|
| **레포 (Repository)** | 프로젝트 폴더. 우리는 화면용 1개, 서버용 1개 |
| **클론 (Clone)** | GitHub 의 프로젝트를 내 컴퓨터로 복사 |
| **브랜치 (Branch)** | 나만의 작업 공간. 여기서 뭘 해도 남에게 영향 없음 |
| **`main`** | 진짜 서비스되는 원본 브랜치. 직접 건드리지 않기! |
| **커밋 (Commit)** | 내 컴퓨터에 "여기까지 저장" 찍기 (게임 세이브) |
| **푸시 (Push)** | 내 커밋을 GitHub 에 올리기 |
| **풀 (Pull)** | GitHub 의 최신 코드를 내 컴퓨터로 받기 |
| **PR (Pull Request)** | "내 작업을 main 에 합쳐주세요" 요청서 |
| **머지 (Merge)** | PR 을 승인해서 main 에 합치기 |
| **충돌 (Conflict)** | 두 사람이 같은 줄을 다르게 고쳐서 Git 이 헷갈리는 상황 |
